# 四川两路电台排查（城市之音 / 岷江音乐）

> **现象**：四川城市之音（FM102.6）、四川岷江音乐（FM95.5）在本应用里放不出来。
> 用户在 <https://www.radio.cn/pc-portal/erji/radioStation.html> 播放这两台"正常"。
>
> **结论**：不是本应用的问题，也不是网络问题 —— **云听（radio.cn）对这两个台下发的
> 全部四条流地址都返回 `HTTP 200 + Content-Length: 0`**，即"连得上、但一个字节都没有"。
> 网页版点击后同样不出声（下文有浏览器实测数据）。

---

## 1. 取证：地址本身是空的

云听的三条地址来自 `/web/appBroadcast/list`，第四条来自 H5 详情接口。
2026-11-02 实测，同一时刻同省台做对照：

| 台 | 地址 | 状态 | 返回字节 |
|---|---|---|---|
| 四川**交通**广播 449 | `130/radios/220449/index_220449.m3u8` | 200 | **338**（`#EXTM3U` 正常） |
| 四川**交通**广播 449 | `130/radios/110449/index_110449.m3u8` | 200 | 300 |
| 四川**交通**广播 449 | `61/radios/10449/index_10449.m3u8` | 200 | 367 |
| 四川**城市之音** 450 | `130/radios/220450/index_220450.m3u8` | 200 | **0** |
| 四川**城市之音** 450 | `130/radios/110450/index_110450.m3u8` | 200 | **0** |
| 四川**城市之音** 450 | `62/radios/20450/index_20450.m3u8` | 200 | **0** |
| 四川**城市之音** 450 | `62/radios/10450/index_10450.m3u8` | 200 | **0** |
| 四川**岷江音乐** 447 | 同上四条（`220447` / `110447` / `20447` / `10447`） | 200 | **0** |

响应头本身是"成功"的，`Content-Type: application/octet-stream`、`Accept-Ranges: bytes`，
`via` 显示走了 `CHN-SCchengdu-AREACT26-CACHE*` 多级 CDN，`X-CCDN-Origin-Time: 123`
说明**回了源站，源站给的就是空文件**。

### 已排除的变量

| 变量 | 试过 | 结果 |
|---|---|---|
| 协议 | `http://` / `https://` | 都是 0 字节 |
| CDN 域名 | `ytcast.radio.cn` / `ytcast2.radio.cn` | 都是 0 字节 |
| 端口线路 | `:80` / `:8555` / `:8556` | 连不上 / 0 字节 |
| 请求头 | 裸 UA、完整浏览器头、`Referer: https://www.radio.cn/`、`Origin`、`Range: bytes=0-`、Cookie 二次请求、HTTP/1.1、HTTP/2 | 都是 0 字节 |
| 客户端 | curl、Python urllib、**Edge 内核（真实浏览器 CORS）** | 都是 0 字节 |
| 平台参数 | `platformCode` = WEB / ANDROID / IOS / APP / PC，两种 `equipmentId` | 地址同格式，都是 0 字节 |
| 出口 IP | 直连 / 走本机 `xray` 代理（`127.0.0.1:10808`，socks5） | 都是 0 字节 |
| 接口 | 省份列表 `/web/appBroadcast/list`、H5 详情 `/contentBiz/appBroadcast/detail/450` | 下发的地址一致，都是 0 字节 |

**签名（key/time）不是原因**：同一次请求里，449 用同一套 key/time 拿到的是正常列表。

## 2. 取证：网页版其实也没有声音

用 Edge 加载 radio.cn 电台页，注入探针后模拟真实点击「四川城市之音」：

```
onclick = playRadio('http://ytcast.radio.cn/130/radios/110450/index_110450.m3u8?type=1&key=...','...','四川城市之音','','','450')
XHR     https://ytcast.radio.cn/130/radios/110450/index_110450.m3u8?type=1&key=...
play()  src=blob:file:///...
---- 5 秒后状态 ----
aud#0 ready=0 paused=false t=0.00 dur=NaN err=-
播放器提示 = 四川城市之音(Live)
```

- `readyState = 0`：**没有拿到任何可解码数据**；
- `currentTime = 0.00`：一帧都没播过；
- 但界面照常显示台名 `四川城市之音(Live)` 和节目名 `享听时间-城市自在听`。

**为什么看起来"正常"**：页面上的"正在直播：xxx"来自接口的 `subtitle` / `liveroomType`
字段（节目单），播放按钮点击后也会切换成暂停样式 —— 这些都是 UI 状态，
与音频有没有数据无关。所以"界面正常、台名正常"并不等于"有声音"。

> 如果确实听到了声音，那大概率点的是下方的**节目回听**（点播 MP3，另一条链路），
> 或者是在「云听」App 里听的（App 与网页共用同一批地址，理论上同样受影响）。

## 3. 曾经的"备用源"为什么也不行

v1.9.7 用过 `satellitepull.cnr.cn`，实测：

| 地址 | 结果 |
|---|---|
| `https://satellitepull.cnr.cn/live/wxsccszs/playlist.m3u8` | 指定 IP 直连 → **404** |
| `https://satellitepull.cnr.cn/live/wxscmjyyt/playlist.m3u8` | 指定 IP 直连 → 超时 |
| 社区源清单自身标注 | 四川城市之音「**近 30 天在线率 0%**」 |

蜻蜓 / 喜马也不是活路：

| 平台 | 结果 |
|---|---|
| 蜻蜓 `ls.qingting.fm/live/1111.m3u8` | 404（老接口已下线） |
| 蜻蜓 `lhttp.qtfm.cn/live/1111/64k.mp3`（含 HMAC-MD5 签名） | 404 |
| 蜻蜓网页播放 | 点击后**零媒体请求**（需登录） |
| 喜马 `live.xmcdn.com/live/755/64.m3u8` | `{"ret":2011,"msg":"电台流获取失败"}` |

**两家平台都报"流获取失败"，和云听的空列表互相印证：这两个台当前没有对外推网络流。**

## 4. v1.9.8 做了什么

| 改动 | 原因 |
|---|---|
| **候选地址里去掉卫星源** | v1.9.7 把它排**第一位**，而它是死链：每次起播先撞 https 超时，干等 15 秒才轮到下一条，比 v1.9.6 更差。`SC_SATELLITE` / `sichuanFallback()` 保留在代码里，恢复后加一行即可复活 |
| **新增 `RadioCnApi.probeHasContent()`** | 播放失败后回后台确认"是连不上，还是连上了没内容"。`200 + 空 body` 的地址记进 `deadUrls`，本次运行内不再使用 |
| **`candidateUrls()` 过滤 `deadUrls`** | 避免每次重试都把已知空地址再喂给播放器、再白等一轮 |
| **失败文案区分** | 所有候选都是空列表时提示「暂无网络直播流（电台侧未推流）」，而不是「连不上」 |
| **单测 `StreamProbeTest`** | 本机 socket 复现三种响应（200 空 body / 200 正常列表 / 404），锁住判据 |

### 电台恢复推流后会不会被"拉黑"？

不会。`deadUrls` 记的是**带一次性 key 的具体地址**，重取一次就是新 URL；
而且只存在本进程内存里，重启即清空。

## 5. 上车怎么验证

1. 切到这两个台，观察 5~10 秒内是否出现「暂无网络直播流（电台侧未推流）」
   —— 出现即说明新逻辑按预期工作（以前是转圈很久才失败）。
2. 看日志 `[取址]` 与 `地址无内容（200 空列表），本次运行内跳过：...`。
3. 对照台（四川交通广播、成都各台）应当一切正常。

> 若某天这两个台恢复了，本应用**不需要改代码**：云听重新下发内容后自动就能播。

## 6. 现场结论确认（2026-11-02）

用户在实际使用环境中确认：**四川岷江音乐（220450）与四川城市之音（220447）当前确实没有信号**，
与本报告第 2、3 节的取证完全一致——不是播放器、不是取址逻辑、不是车机兼容性问题。

结论闭环：

| 环节 | 状态 |
|---|---|
| 云听接口取址 | 正常，四条地址都能下发（带一次性 key） |
| 源站响应 | 200 + `Content-Length: 0`（`X-CCDN-Origin-Time` 已回源） |
| radio.cn 网页播放 | 同样无声音（`readyState=0`） |
| 蜻蜓 / 喜马拉雅 | 1111、1110 全 404；喜马 `ret:2011` |
| 卫星源 | 404 |
| 用户侧确认 | 无信号 |

v1.9.8 的处理（候选剔除卫星源 + 空地址记 `deadUrls` + 文案区分）保持不变，
属于「电台不推流时给出准确提示」的兜底，而不是修复源站。
**电台侧恢复推流后，本应用无需改动即可自动可播。**
