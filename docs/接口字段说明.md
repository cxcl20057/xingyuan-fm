## 1. 请求规范

### 1.1 基础信息

| 项 | 值 |
|---|---|
| 网关地址 | `https://ytmsout.radio.cn` |
| 方法 | 全部 `GET` |
| 参数位置 | URL query（单参数接口会拼进路径，见 1.4） |
| 响应格式 | JSON（`Content-Type: application/json`） |

### 1.2 请求头（必须）

| Header | 值 | 缺失后果 |
|---|---|---|
| `Content-Type` | `application/json` | — |
| `equipmentId` | `0000` | 未单独验证 |
| `platformCode` | `WEB` | 实测**缺失仍返回正常**，但建议带上 |
| `timestamp` | 当前毫秒时间戳，如 `1792722303000` | <b class="ok">已验证</b> 缺失 → `code=1001 参数不合法` |
| `sign` | 见 1.3 | <b class="ok">已验证</b> 缺失或错误 → `code=1001` |
| `User-Agent` | 任意浏览器 UA | 建议带 |

### 1.3 签名算法 <b class="ok">已验证</b>

```
sign = UPPER( MD5( sortByKey(参数) + "&timestamp=" + ts + "&key=" + KEY ) )
```

- `KEY = f0fc4c668392f9f9a447e48584c214ee`（前端源码公开常量）
- `sortByKey(参数)`：把所有 query 参数**按键名字母升序**拼成 `k=v&k=v`
- 参数为空时，**直接以 `timestamp=` 开头，不加前导 `&`**

**已验证的对照值（ts = 1700000000000）**，可用来校验自己的实现：

| 参数 | sign |
|---|---|
| 空参 | `87E86F1CF502D0DD091305F7749B30F0` |
| `provinceCode=510000` | `554F407F527047F71201E3B39DE95DBF` |
| `categoryId=0&provinceCode=510000` | `5C9578E663E0B97038178E0EA24DDB35` |

> <b class="ok">已验证</b> 参数**传入顺序不影响结果**（内部会排序），实测倒序传入得到同一签名。

**注意 timestamp 超时** <b class="ok">已验证</b>：用 1 小时前的时间戳请求 → `code=1050 访问请求过期`。
所以**不要在客户端缓存签名结果**，每次请求现算。

### 1.4 单参数特例 <b class="warn">待确认</b>

官网源码里有一条规则：**当参数只有 1 个时，会把值拼进路径**（`/path/值`），而不是放 query。

本项目用到的两个接口都是 0 参数或 2 参数，所以没触发。若要调用其它接口，注意这条。

## 3. 接口二：电台列表（含播放地址）

```
GET /web/appBroadcast/list?categoryId=0&provinceCode=510000
```

### 3.1 请求参数 <b class="ok">已验证</b>

| 参数 | 必填 | 说明 |
|---|---|---|
| `categoryId` | 建议必填 | 分类筛选，见 3.2。**`0` = 全部** |
| `provinceCode` | 是 | 省份编码。`0` 或不传 = 国家台（19 台） |

**参数边界实测** <b class="ok">已验证</b>：

| 现象 | 结果 |
|---|---|
| 不传 `categoryId` | 仍返回该省全部台（四川 44 台），等同 `0` |
| `provinceCode` 传空 | 返回国家台 19 个（等同 `0`） |
| `provinceCode=999999`（不存在） | `code=0`，`data=[]`，**不报错** |
| `categoryId` 传非 0 的任意值（如 `1`、`-1`、`abc`） | 都返回 **52 台**（44 + 8），含义不明 <b class="warn">待确认</b> |

> <b class="warn">待确认</b> **建议只用 `categoryId=0`**。传 1 会多出 8 个台（如「935爱旅游」「成都经典946」「宜宾综合广播」），
> 这 8 个台在 `categoryId=0` 里查不到，可能是测试/灰度数据，稳定性未知。

### 3.2 分类列表 <b class="ok">已验证</b>

另有一个分类接口（`GET /web/appCategory/list/all`，无参数），返回 10 个分类：

| id | 名称 | | id | 名称 |
|---|---|---|---|---|
| 0 | 全部 | | 17 | 综艺 |
| 7 | 热门 | | 5 | 音乐 |
| 9 | 新闻 | | 19 | 故事 |
| 11 | 财经 | | 21 | 民族 |
| 13 | 生活 | | — | — |
| 15 | 交通 | | | |

**分类筛选是真的生效的** <b class="ok">已验证</b>（四川实测：全部 44 / 交通 15 / 新闻 17 / 音乐 8）。
若非要做「按类型筛选」，用这里的 id 即可。

### 3.3 响应结构 <b class="ok">已验证</b>

```json
{
  "code": 0,
  "message": "SUCCESS",
  "data": [
    {
      "contentId": "749",
      "title": "中国交通广播（四川）",
      "subtitle": "正在直播：新闻面对面",
      "image": "https://ytmedia.radio.cn/25010/adfile/202505/19/18/dQlA....jpg",
      "playUrlLow":    "http://ytcast.radio.cn/72/radios/10749/index_10749.m3u8?type=1&key=...&time=6adac586",
      "mp3PlayUrlLow": "http://ytcastmp3.radio.cn/72/stream_10749.mp3?type=1&key=...&time=6adac586",
      "mp3PlayUrlHigh":"http://ytcastmp3.radio.cn/72/stream_20749.mp3?type=1&key=...&time=6adac586",
      "playUrlMulti": ""
    }
  ],
  "extInfo": null
}
```

> <b class="ok">已验证</b> **字段就这 8 个，没有节目单/时段字段**。用 `subtitle` 显示当前节目名，用 `00:00-24:00` 占位时间轴。

### 3.4 字段明细

| 字段 | 类型 | 填充率（四川 44 台） | 说明 |
|---|---|---|---|
| `contentId` | string | 44/44 <b class="ok">已验证</b> | **电台唯一 ID**（数字字符串，如 `"749"`）。续播、收藏、隐藏都用它做键 |
| `title` | string | 44/44 <b class="ok">已验证</b> | 台名。有「中国交通广播（四川）」这种带括号的 |
| `subtitle` | string | 44/44 <b class="ok">已验证</b> | **当前节目名**。44 台里 33 台是占位文案 `暂无节目单`，其余是 `正在直播：XXX` |
| `image` | string | 44/44 <b class="ok">已验证</b> | 台标图 URL（图片是 HTTPS，播放流是 HTTP，注意区分） |
| `playUrlLow` | string | 44/44 <b class="ok">已验证</b> | 低码率流。**多为 m3u8** |
| `mp3PlayUrlLow` | string | 39/44（四川）<b class="ok">已验证</b> | 名义上是「低码率 MP3」，**实际格式因省而异** |
| `mp3PlayUrlHigh` | string | 39/44（四川）<b class="ok">已验证</b> | 名义上是「高码率 MP3」，同上 |
| `playUrlMulti` | string | **0/44**（四川）<b class="ok">已验证</b> | 多码率流。**绝大多数省份为空字符串** |

### 3.5 各字段的真实格式（关键！）<b class="ok">已验证</b>

按省份实测，同名字段的实际协议**完全不同**：

| provinceCode | `playUrlMulti` | `mp3PlayUrlLow` | `mp3PlayUrlHigh` | `playUrlLow` |
|---|---|---|---|---|
| `0`（国家） | **m3u8** ×19 | **m3u8** ×19 | **m3u8** ×19 | m3u8 ×19 |
| `110000`（北京） | 空 ×5 | m3u8 ×3 | m3u8 ×3 | m3u8 ×5 |
| `510000`（四川） | 空 ×44 | **mp3** ×39 | **mp3** ×39 | m3u8 ×44 |
| `440000`（广东） | 空 ×47 | **mp3** ×32 | **mp3** ×32 | m3u8 ×47 |
| `310000`（上海） | 空 ×7 | **mp3** ×5 | **mp3** ×5 | m3u8 ×7 |
| `460000`（海南） | 空 ×10 | **mp3** ×7 | **mp3** ×7 | m3u8 ×10 |

**结论**：
- `playUrlLow` 是最稳定的——**各省都有值，且都是 m3u8**。
- `mp3PlayUrlLow/High` 名字骗人：北京/国家台给的是 m3u8，只有四川/广东/上海/海南这些给真 mp3。
- **必须按 URL 判断**：含 `.m3u8` → HLS 播放器；含 `.mp3` → 直接流。

### 3.6 域名与协议 <b class="ok">已验证</b>

| 域名 | 出现次数 | 用途 |
|---|---|---|
| `ytcast.radio.cn` | 171 | HLS（m3u8） |
| `ytcastmp3.radio.cn` | 170 | MP3 流 |
| `ytcast2.radio.cn` | 55 | 国家台 HLS |
| `ytlive.radio.cn` | 19 | 国家台 HLS |

台标图片域名：`ytmedia.radio.cn`（60 次）、`ytdem.radio.cn`（2）、`iovimg.radio.cn`（1）。

> <b class="ok">已验证</b> **播放流 415 个 URL 全部是 `http://`，零个 https。**

## 4. 播放地址结构（重点）

### 4.1 URL 形态 <b class="ok">已验证</b>

```
http://ytcastmp3.radio.cn/72/stream_10749.mp3?type=1&key=<32位小写hex>&time=<8位hex>
http://ytcast.radio.cn/72/radios/10749/index_10749.m3u8?type=1&key=<32位hex>&time=<8位hex>
```

| 参数 | 含义 | 实测结论 |
|---|---|---|
| `type` | 固定 `1` | 未发现其它取值 |
| `key` | 32 位十六进制签名 | <b class="warn">待确认</b> **无法本地生成**，只能从接口取 |
| `time` | 8 位十六进制 | <b class="ok">已验证</b> **就是签发的 Unix 秒**（十进制 1792722303 = 2026-10-23 10:25:03） |

### 4.2 `key` 能否自己算？<b class="bad">不支持</b> 不能 <b class="warn">待确认</b>

试过 7 种常见拼法（`md5(time)`、`md5(path)`、`md5(path+time)`、`md5(time+path)`、`md5(path+KEY)`、`md5(KEY+path)`、`md5(path&time&key)`），**全部不匹配**。

> **结论：`key` 是服务端用未知密钥算的，客户端无法生成。**
> 好在**不需要生成**——接口每次都返回现成地址。这直接决定了缓存策略（见 4.4）。

### 4.3 地址有效期 <b class="ok">已验证</b>

| 测试 | 结果 |
|---|---|
| 同一秒内两次请求 | `key` 与 `time` **完全相同** → 是按「时间片」派生的，不是一次性随机 |
| 篡改 `time`（+1 小时） | <b class="ok">已验证</b> **立刻 HTTP 403 Forbidden** → 服务端严格校验 key/path/time 三元组 |
| 原样保存的地址放置 32 分钟 | <b class="ok">已验证</b> 仍可拉流（HTTP 200/206） |
| 原样保存的地址放置 6 小时以上 | <b class="warn">待确认</b> 未实测出确切过期点，保守按 30 分钟用 |

**落地建议**：

```
缓存 TTL = 30 分钟（新鲜期，直接复用）
硬过期   = 6 小时（超过必须重新申请）
失败处理 = 一旦 403/404，立刻重新拉整省列表换新地址
```

### 4.4 拉流验证 <b class="ok">已验证</b>

| 字段 | 响应 | Content-Type |
|---|---|---|
| `mp3PlayUrlLow` | `HTTP/1.1 200 OK` | `audio/mpeg`（带 `icy-pub: 0`，是 Icecast 风格直播流） |
| `mp3PlayUrlHigh` | `HTTP/1.1 200 OK` | `audio/mpeg` |
| `playUrlLow` | `HTTP/1.1 206 Partial Content` | `application/octet-stream`（m3u8 清单文件） |

> 直播流是**无限长度**的，验证时**务必用 `Range: bytes=0-0` 或 `curl -r 0-0` 只取 1 字节**，
> 否则会一直读下去不返回（我第一次就卡在这）。播放器本身没问题，但**自检脚本要小心**。

内容协商测试 <b class="ok">已验证</b>：换 `Accept: application/x-mpegURL` 不会改变返回格式，**服务端不按 Accept 协商**。

## 5. 错误码 <b class="ok">已验证</b>

所有错误都是 **HTTP 200** + 业务码，不会返回 4xx/5xx。

| code | message | 触发条件 |
|---|---|---|
| `0` | `SUCCESS` | 正常 |
| `1001` | `参数不合法` | 缺 `timestamp` 头；缺 `sign` 头 |
| `1001` | `网关拦截GET无参数验签错误` | `sign` 值错误（如全 0） |
| `1050` | `访问请求过期` | `timestamp` 与服务器时间偏差过大（1 小时前已失败） |

**处理建议**：`code != 0` 一律**重新取时间戳并重算签名后重试 1 次**；仍失败则提示网络问题，不要直接崩溃。

## 6. 建议的调用时序

```
① GET /web/appProvince/list/all          → 省份下拉 + 定位后校验省份合法性
② GET /web/appBroadcast/list?categoryId=0&provinceCode=<目标省>
   → 拿到该省全部台的 contentId / title / image / 4 个播放地址
③ 播放时：
   a. 查本地缓存（contentId → 地址，30 分钟内）→ 命中直接播（秒开）
   b. 未命中 → 已从 ② 拿到地址 → 直接播
   c. ③ 失败 → 重新请求 ② ，找到同 contentId 的台，取新地址重试
④ 台标：image 字段单独下载，本地磁盘缓存（服务端返回 Cache-Control: max-age=2592000，即 30 天）
```

**注意**：没有「按 contentId 单独取地址」的公开接口。刷新单台地址只能**重拉整个省列表**，
副作用是顺带刷新了同省所有台的地址（对缓存反而是好事）。

## 7. 合规边界

| 项 | 要求 |
|---|---|
| 接口性质 | 网页端**公开接口**，KEY 来自公开 JS 文件 |
| 允许 | 读取台列表与播放地址、播放音频 |
| **禁止** | 下载/转存/分发音频文件；绕过任何鉴权；用于商业转售 |
| **禁止** | 高频轮询（作为服务端数据源批量抓取），这是给客户端实时播放用的 |
| 台标图 | 属央广版权素材，仅用于展示对应电台，不得单独分发 |
| 稳定性 | 服务端**无 SLA**，KEY 可能轮换。**网关地址与 KEY 要做成可远程配置**，避免一次变更全线崩溃 |
