# 本地构建环境（Windows，免管理员）

> 本文记录本机（Windows 11 Enterprise LTSC 26100）上搭起来的一套 Android 构建工具链。
> 全部装在 **D 盘**、**不写系统环境变量**、**不需要管理员权限**，删掉 `D:\dev` 即完全卸载。
> 目的是让「改完代码立刻能出 APK」，不必每次都推到构建机。

---

## 二、怎么用

```powershell
# 每个新开的 PowerShell 窗口先执行一次（只影响当前会话）
. D:\dev\env.ps1
```

之后正常 Gradle 命令即可：

```powershell
cd C:\Users\cxcl20057\WorkBuddy\2026-10-31-19-51-43\carlink

# 出 Carlink 包（换白名单包名）
gradle :app:assembleCarlinkRelease -PtargetPkg=net.joydao.radio

# 出正式包
gradle :app:assembleOfficialRelease

# 跑单测（Windows 上会跳过 6 个渲染类，见第四节）
gradle :app:testCarlinkDebugUnitTest
```

产物位置：

```
app/build/outputs/apk/carlink/release/星愿FM-Carlink-<版本>.apk
app/build/outputs/apk/official/release/app-official-release.apk
```

### 想让环境变量长期生效（可选）

`D:\dev\env.ps1` 末尾有三行注释掉的 `SetEnvironmentVariable(..., 'User')`，
取消注释再执行一次即可写入「用户环境变量」（仍然不需要管理员）。
**不建议**写进系统环境变量：会和机器上其他 Android 项目抢 `JAVA_HOME`。

## 三、踩过的四个坑

### 坑 1：`local.properties` 里的 Windows 路径转义

Java Properties 把反斜杠当转义符，`sdk.dir=D\:\dev\android-sdk` 会被解析成
`D:devandroid-sdk`（`\:` → `:`，`\d` → `d`），AGP 报
`IOException: 文件名、目录名或卷标语法不正确`。

正确写法用正斜杠：

```properties
sdk.dir=D:/dev/android-sdk
```

### 坑 2：`sdkmanager` 装 platform-34 撞 429

`sdkmanager "platforms;android-34"` 会报
`Server returned HTTP response code: 429`（Google 限流），装出来的
`platforms/android-34` 是空目录、`platform-tools` 也是空目录。

改用 curl 直接下 zip 再解压即可：

```bash
curl -o platform-34.zip https://dl.google.com/android/repository/platform-34-ext7_r03.zip
tar -xf platform-34.zip -C /d/dev/android-sdk/platforms
```

注意 Windows 上要用 `C:\Windows\System32\tar.exe`（bsdtar，认 zip）；
Git Bash 自带的 `tar` 是 GNU tar，**不认 zip**，会报 `This does not look like a tar archive`。

### 坑 3：`cmd //c "sdkmanager.bat \"platforms;android-34\""` 把引号传进去了

从 Git Bash 经 `cmd //c` 嵌套调用时，引号会被当成包名的一部分，
报 `Warning: Failed to find package '"platforms;android-34"'`。
**直接从 Bash 调用 `.bat`** 即可，不要套一层 `cmd //c`。

### 坑 4：Robolectric 在 Windows 上跑不了渲染测试

见下一节，这是硬限制，不是配置问题。

## 四、Windows 上跑单测的限制（重要）

### 现象

任何真正构造 `View` 的测试都会抛：

```
java.lang.IllegalArgumentException:
  resource native/windows/x86_64/robolectric-nativeruntime.dll not found.
    at org.robolectric.nativeruntime.DefaultNativeRuntimeLoader.loadLibrary
    at org.robolectric.shadows.ShadowNativeRenderNodeOP.nCreate
    at android.view.RenderNode.nCreate
    at android.view.View.<init>
```

### 根因

Robolectric 4.10 起图形栈**全面 native 化**，需要
`native/<os>/<arch>/robolectric-nativeruntime` 动态库。
**上游只发布了 linux 与 mac 版本，没有 Windows 的 DLL**（这不是本项目的配置问题）。

已验证过、但**无效**的绕法：

| 尝试 | 结果 |
|---|---|
| `robolectric.graphicsMode=LEGACY`（系统属性） | 属性确实传进了测试 JVM（`--info` 的 worker 命令行可见 `-Drobolectric.graphicsMode=LEGACY`），但 4.11.1 仍走 `ShadowNativeRenderNodeOP`，已无纯 Java 回退实现 |
| `app/src/test/resources/robolectric.properties` 里写 `graphicsMode=LEGACY` | 同上，无效（该文件已删除） |
| WSL | 本机 `wsl.exe` 存在但**无已安装发行版**，安装需管理员 + 重启 |
| Docker | 未安装 |

### 处置（已写进 `app/build.gradle` 的 `testOptions`）

Windows 上自动排除 6 个「必须真正渲染 / 布局」的测试类：

| 类 | 依赖 |
|---|---|
| `CarScreenTest` | 车机两栏布局 measure/layout |
| `PhoneScreenTest` | 手机单列布局 measure/layout |
| `PhoneScreenSmallTest` | 小屏布局 |
| `UiRenderTest` | 截图渲染 |
| `FavoriteKeepsScrollTest` | ListView 真实布局与滚动位置 |
| `ListFollowsPlaybackTest` | 同上 |

**Windows 上实际执行 197 项，0 失败**（含全部版面判据 `PhoneLayoutTest` 14 项）。
**Linux / mac 构建机不受影响，仍然全量跑**，出包前的完整验证在那边完成。

排除逻辑只在 `os.name` 含 `windows` 时生效，构建机行为完全不变。

### 另一个坑：`LiveReleaseProbeTest` 会卡住

该测试真的请求 Gitea API。网络不通时本应被 `Assume` 跳过，
但若连接是**挂起**（不是立刻失败），测试会一直等 TCP 超时——
实测卡了 16 分钟，CPU 只涨了 3 秒。

跑测试时加上环境变量即可：

```bash
LIVE_UPDATE=0 gradle :app:testCarlinkDebugUnitTest
```

## 六、卸载

```powershell
Remove-Item -Recurse -Force D:\dev
```

`local.properties`（含 `sdk.dir`）在 `.gitignore` 里，不会进仓库。
