> **结论**：v2.0 的喜马拉雅风格保留并深化，新增白天 / 夜间两套完整色板；
> 顶栏加「自动 / 白天 / 夜间」三态切换，默认跟随车机系统。

## 1. 技能检索结论：用了什么、没用什么

按技能流程先跑 `--design-system`，再补检索 style / color / ux，并读了
`references/pro-rules.md` 与 `quick-reference.md` 的暗色规则。

| 检索 | 数据库给的结果 | 是否采用 | 理由 |
|---|---|---|---|
| `--design-system "in-car radio entertainment audio light dark minimal orange content-first"` | Pattern: Newsletter / Content First；Style: Vibrant & Block-based（Light ✓ / Dark ✓）；配色 `#1E293B` + `#DC2626`；字体 Righteous + Poppins | **只采用「双模式都要做」这一条** | 命中结果是 Web 落地页 / 营销页，不是车载音频界面；红色 CTA 与英文展示字体跟本项目已验证的喜马拉雅语言冲突，照搬会把车机界面做成订阅页 |
| `--domain style "audio entertainment content-first minimal card light dark"` | Voice-First Multimodal（Light ✓ / Dark ✓）、Dark Mode (OLED) | **采用规则，不采用色板** | OLED 那条要求「纯黑 + 霓虹」，车机是 LCD，纯黑配亮白字有光晕；Voice-First 的「大触控目标 / 最小 chrome」用上了 |
| `--domain color "dark mode orange accent contrast"` | Digital Signage / Kiosk：`#020617` 底 + `#EF4444` 强调 | **不采用** | 数据库没有「橙色 + 浅色底」的车载组合；按 `color-dark-mode` 规则自己做去饱和 tonal 变体 |
| `--domain ux "dark mode contrast touch target accessibility"` | 4.5:1 文字、44×44 触控、8px 间距、避免灰字压灰底 | **全部采用** | 这四条正是本次审计抓到问题的依据 |
| `--domain ux "animation accessibility z-index loading"`（交付前验证 pass） | 加载反馈、减少持续动画、层级管理 | **采用前两条** | 车机界面上一秒都不该有东西自己动，不新增动效 |

**Stack**：项目是 Android framework `Activity` + Java + XML 资源（无 package.json / pubspec），
技能的 stack 列表里没有 Android XML，因此跳过 `--stack`，改用 `pro-rules.md`
（其适用范围明确写了 native/Android app UI）作为实现规范。

## 3. 双主题怎么落地

### 3.1 三态

| 档位 | 顶栏显示 | 行为 |
|---|---|---|
| 跟随系统（默认） | 自动 | 车机 `uiMode` 切夜间时自动换色板 |
| 白天（强制） | 白天 | 无视系统夜间态 |
| 夜间（强制） | 夜间 | 无视系统白天态 |

点顶栏胶囊循环三档，存 `SharedPreferences`；「关于」里显示当前档位。
文字用「自动 / 白天 / 夜间」而不是 ☀/☾ 字符或 emoji —— 车机字体库裁过这类 glyph，
v2.0 已经因为「⊘」踩过一次方框。

### 3.2 为什么不引入 AppCompat

本工程是 framework `Activity` + `Theme.Material.*`，没有 appcompat。
换 `AppCompatDelegate.setDefaultNightMode()` 要新增依赖，会连累 Carlink 白名单包的
dex 与既有单测。改用 `Activity.attachBaseContext()` 里
`createConfigurationContext()` 覆盖 `Configuration.uiMode` 的夜间位，
让系统自己按 `values-night/` 限定符选资源 —— 纯 framework、零新依赖、API 17+ 可用。

### 3.3 最容易漏的一坑

`AndroidManifest.xml` 的 `MainActivity` 声明了
`android:configChanges="...|uiMode|..."`：**系统切夜间时 Activity 不重建**，
只回调 `onConfigurationChanged`。已经 inflate 出来的 drawable / ColorStateList
不会自己重读资源，光放 `values-night/` 等于没做。

所以 `MainActivity.onConfigurationChanged()` 里拿「本次 onCreate 生效的夜间态」
和新的系统 `uiMode` 比一次，不一致就 `recreate()`；手动白天 / 夜间两档直接跳过这个分支。
这段代码是双主题能不能真在车上生效的关键，不是可选项。

### 3.4 新增 / 改动的文件

| 文件 | 作用 |
|---|---|
| `res/values-night/colors.xml` | 夜间全部颜色（与白天同名同角色） |
| `res/values-night/styles.xml` | 夜间 `AppTheme`：父主题改 `Theme.Material.NoActionBar`、`windowLightStatusBar=false`，让 AlertDialog / 系统栏一起变暗 |
| `java/.../ThemeMode.java` | 三态持久化、`wrap(Context)`、`effectiveNight()` 纯函数 |
| `java/.../ColorContrast.java` | WCAG 相对亮度 / 对比度，纯 JVM 可跑 |
| `java/.../CoverInitial.java` | 列表首字封面取字（跳过括号等符号） |
| `MainActivity.java` | `attachBaseContext`、`onConfigurationChanged`、顶栏按钮、列表首字封面 |
| `drawable/cover_chip*.xml`、`accent_chip.xml` | 首字方块 / 地区胶囊 |
| `scripts/check_contrast.py` | 读真实 XML 逐对核算色板 |

| 角色 | token | 白天 | 夜间 |
|---|---|---|---|

| 选中底上的字 | `accent_deep` | `#C2410C` | `#FFB27A` |
| 文字 1 / 2 / 3 | `text_primary` / `text_secondary` / `text_hint` | `#16181D` / `#5A6270` / `#7A828E` | `#F2F4F8` / `#AEB6C4` / `#8A93A1` |
| 封面底 / 字 | `cover_bg` / `cover_text` | `#F2F4F7` / `#5A6270` | `#232935` / `#AEB6C4` |
| 次要图标 | `icon_secondary` | `#4A5058` | `#C7CEDB` |

夜间不是白天反相：三层明度递进（底 `#0D1015` → 卡 `#191D24` → 次级面 `#232935`），
带一点冷蓝，和橙色形成温和冷暖对比；不用纯黑，因为车机是 LCD 不是 OLED。

### 两套橙，别混用

- `accent` 亮橙只画「不承载文字」的东西：直播圆点、时间轴指针、正在播 3dp 指示条、焦点描边。
- `accent_solid` 深橙专门承载白字 / 白图标：主播放键、选中标签。
- `accent_deep` 是浅橙底上的强调文字，白天压深、夜间提亮，两套都 ≥ 4.5:1。

这样「橙只代表正在播」的语言不变，同时把 v2.0 那处 2.94:1 的小字问题修掉。

## 6. 喜马拉雅风格深化（除了双主题，这一版还改了什么）

| 改动 | 说明 |
|---|---|
| 列表行首字封面 | 数字序号换成 40dp（车机）/ 32dp（手机）圆角方形首字块，选中时跟整行一起变浅橙。喜马拉雅是封面驱动的内容列表，每行有个独立锚点更好扫视。车机用 `6+40+10=56dp`，与旧版 `12+32+12=56dp` 完全相等，台名可用宽度不变，「四川交通广播（FM101.7）」不会被挤成省略号 |
| 顶栏触控目标 | 车机胶囊 36→48dp、手机工具行 32→48dp；`region_bg` 圆角 20→24dp 配新高度；地区按钮单独用 `accent_chip`（24dp 圆角），`time_chip` 留给时段小标签 |
| 图标全矢量 + token | 5 个白色 `fillColor` 改 `@color/icon_on_accent`，6 处硬编码改语义 token；夜间不会再出现「某颗心形还是白的」 |
| 状态反馈 | `surface_pressed` 在两套主题都有明显压暗；焦点态仍是白底 + 2dp 橙描边，夜间用亮橙描边同样可辨 |
| 布局比例 | 左 46% / 右 54%、台标 140dp、手机 `logo_wrap` 44dp（`PhoneLayout.isMiniBar()` 的判据）全部不动，避免引入车机实车回归 |
| 动效 | 没有新增。车机界面上一秒都不该有东西自己动 |

## 9. 没做的 / 遗留

- **实车夜间联动**：`跟随系统` 依赖车机真的改 `Configuration.uiMode`。若吉利银河 E22H 只在系统 UI 变暗、不下发 `uiMode`，会自动停在白天 —— 这时点两下顶栏切「夜间」即可。上车验证方法：开大灯 / 切车机夜间主题，看界面是否自动换；没换就说明厂商没下发，属预期。
- **台标占位插画**：仍是台名首字，没做插画式占位。
- **正式版自动更新**：`com.rea.radio` 仍指向私有仓库 `xinyuan-radio`（匿名 404），未修；不能把该仓库设 public（会公开 `keystore/` 与签名口令）。
- **v2.0.0 的 Release 不动**：本版只是本地归档 + 源码提交，没有覆盖线上任何 Release。
