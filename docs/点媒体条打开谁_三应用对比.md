# 点媒体条为什么会打开别人（v1.9.11 调查记录）

> 素材：1.9.10 实车录屏（点了媒体条弹出云听小窗「当前暂无播放内容」）、
> 无界空间演示录屏（点了媒体条回到正在播放的界面）。两个 apk 都在项目资产里。

## 一、两段录屏各自发生了什么

| 录屏 | 现象 |
|---|---|
| 1.9.10 实车 | 底部媒体条写着我们的「四川新闻广播」，点一下弹出**云听的小窗**，里面写「当前暂无播放内容 / 去云听」 |
| 无界空间演示 | 底部媒体条写着「眉山综合广播」，点一下**回到那个正在播的界面**（播放页，显示 正在播放） |

关键差别不是界面长相，而是**点开的是谁**：一个是「被车机当成当前媒体源的 App」，
另一个是「我们自己的 App」。

## 二、把三个 apk 的清单摆在一起看

| 应用 | 包名 | 媒体中心集成方式 | 点媒体条 |
|---|---|---|---|
| 酷我车机版 6.0.0.9 | `cn.kuwo.kwmusiccar` 系 | 只用 EAS（`registerMusic` + `updateMediaSourceTypeList(6)`）；**无** gcmediacenter、**无** `BROADCAST_MEDIA_CENTER` | ✅ 打开自己 |
| 云听 3.0.2 | `com.edog.car` | EAS + 接收 `ecarx.xsf.mediacenter.action.BROADCAST_MEDIA_CENTER`（语音语义用）+ 系统媒体源清单成员 | ✅（它就是车机默认选中的那个） |
| 无界空间 2.125 | `com.geely.gc.cloudautoclient` | 暴露 `com.geely.gcmediacenter.service.START_BINDER_SERVICE`（自己实现 `IGCMediaCenter` AIDL，车机反向 bind 它）+ `MEDIA_BUTTON` 接收器 | ✅ 打开自己 |
| 本应用 1.9.x | `net.joydao.radio` | 只用 EAS，与酷我**同构**（v1.9.7 起） | ❌ 打开云听 |

三条可复现的结论：

1. **不是 EAS 报什么的问题。** 我们已经和酷我完全同构（类型 6、`updateCurrentSourceType(6)`、
   每次 push 复查焦点），媒体条也能显示我们的台名 —— 说明 EAS 这条链路是通的。
2. **不是「有没有 MSESSION / MediaSession」的问题。** 我们 `setSessionActivity` 一直在，
   方向盘按键也早就通。
3. **差别在「车机媒体源清单」里有没有我们。** 酷我、云听是厂商预置进清单的；
   无界空间是**自己实现车机的 binder 服务**（`IGCMediaCenter`）注册进去的。
   点媒体条 = 打开清单里当前被选中的那一项；我们不在清单里，所以永远是别人。

## 三、云听那个「当前暂无播放内容」说明了什么

那不是一个在播的应用被点开，而是**媒体中心拉起「当前源 App」的卡片页**，
云听此刻没在播，就显示占位 + 「去云听」按钮。也就是说车机认的「当前源」是云听，
不是我们。这个判据和媒体条显示什么**无关**（媒体条读的是 EAS 推上去的播放信息）。

## 四、可选的三条路（按成本排）

| 方案 | 做法 | 成本 | 风险 |
|---|---|---|---|
| **A. 包名伪装** | 把 applicationId 换成一个已在清单里的包名（如喜马拉雅车机版 `com.ximalaya.ting.android.car`，或云听 `com.edog.car`），替装掉原来那个 | 5 分钟，改一行 + 重打包 | 真 App 不能共存；收藏数据要重装后重建；若车机同时校验签名则无效（但一次实验就能证伪） |
| **B. 实现车机 binder 服务** | 照无界空间的做法，在清单里声明 `com.geely.gcmediacenter.service.START_BINDER_SERVICE`，自己实现 `IGCMediaCenter`（AIDL 可从无界空间 dex 里还原） | 1~2 天，要还原 AIDL（`IGCMediaCenter` / `GCMediaInfo` / 两个 listener） | 接口语义只能靠反编译推断；厂商可能校验签名或包名前缀 `com.geely.*` |
| **C. 车机侧加白名单** | adb/root 进车机，把 `net.joydao.radio` 加进媒体源清单（配置或数据库），重启媒体中心 | 半小时，但需要车机 adb/root | 之前为「方向盘按键」改过 `appSource.xml` / `tb_media_app_info`，那两张表不影响按键；但**可能**正是点媒体条的判据 |

## 五、建议顺序

1. 先做 **A**（一次就能证伪「按包名路由」这个假设）：
   - 如果换成云听包名后点媒体条回到我们 → 说明判据是包名，接着决定长期用哪个身份；
   - 如果还是弹云听 → 说明还有签名/白名单校验，直接转 C。
2. 若 A 无效且有 adb → 做 **C**（比 B 便宜得多）。
3. B 只在 A、C 都走不通、且用户能接受「靠反编译接口硬啃」时再上。

> 本文只记录证据与方案，不含未验证的结论。1.9.11 本身只修了滑列表误切台，
> 与本节无关。
